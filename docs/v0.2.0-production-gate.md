# v0.2.0 Production Gate Contract

This document is the compatibility and release contract for the production
deployment line. It supplements the v0.1.x API contract; it does not rewrite
historical scans, findings, SBOMs, assessments or waivers.

## Release boundaries

v0.2.0 delivers a highly available API/worker control plane, managed MySQL and
object-storage integration points, OIDC plus API-key authentication, registry
credential references, durable supply-chain evidence metadata, Prometheus and
OpenTelemetry hooks, and tested backup/recovery procedures.

Kubernetes Admission, cluster inventory and runtime eBPF detection remain
separate follow-on adapters. v0.2.0 does not run a full Trivy scan inside an
Admission request and does not make missing runtime telemetry a release pass.

## Compatibility invariants

- Existing `/api/v1` clients may ignore additive response fields.
- API keys retain hash-at-rest, tenant, scope, expiry, revocation and audit
  semantics. OIDC identities are mapped to an existing tenant server-side.
- `pass` means only that the current policy and trusted evidence passed. It is
  not a statement that an artifact is free of all vulnerabilities.
- Migrations are append-only, checksum verified and additive-first. API and
  worker processes never run DDL during startup.
- Historical evidence is immutable. New evidence rows or object references do
  not alter prior gate decisions.

## Production gate evidence

An v0.2.0 release candidate is not production-ready until the staging gate
contains all of the following evidence:

1. Helm lint/template output and a disposable Kubernetes deployment with API
   and worker replicas, probes, PDB and NetworkPolicy.
2. Managed-MySQL connectivity, TLS and failover results with the configured
   connection budget.
3. Object-store write/read/integrity and orphan-cleanup results.
4. OIDC issuer/JWKS rotation tests and API-key regression tests.
5. Registry authentication, throttling and credential-redaction tests.
6. Prometheus scrape and OpenTelemetry trace correlation checks.
7. Encrypted backup restore, migration replay and tenant-isolation checks.
8. Capacity and 24-hour soak results with measured RPO/RTO. Historical
   v0.1.0 measurements are regression evidence only, not an SLA.
